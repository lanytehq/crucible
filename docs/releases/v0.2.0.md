# Lanyte Crucible v0.2.0

Contract release since v0.1.0. It adds a local runtime-control family,
Chanvoy wait and follow RPC methods, and a provider-neutral mail policy
family. Existing numbered IPC schema files are unchanged.

Publishing these contracts does not qualify a consumer implementation
or a native process lifecycle. ADR-0018 and DDR-0001 remain Proposed.
Tags are signed manually by the supervisor; CI never signs. Verify the
signature on the published tag.

## Added

### Local runtime-control v1

`schemas/ipc/local/` holds Chanvoy runtime-control v1. Nine selected
roots cover retirement RPC request and response, observation RPC
request and response, protocol errors, missing-acknowledgement
reports, bootstrap, readiness, and CLI lifecycle observations. The
manifest has 100 conformance cases. Family semantics and byte budgets
live beside the schemas. `make check-chanvoy-runtime-control-v1`
checks meta-validity, exact root selection, and those cases.

The numbered gateway loader does not recurse into this directory.
Validate the root your transport selected. A numbered-channel pass
does not validate this family.

### Chanvoy daemon RPC

`schemas/common/chanvoy-daemon-rpc/v0/` adds process-held channel
follow (`wait_follow_v1`, `wait_follow_v2`), named-DM wait and follow
(`wait_dm_v1`, `wait_dm_follow_v1`, `wait_dm_follow_v2`), and inbox
wait and follow (`wait_inbox_v1`, `wait_inbox_follow_v1`,
`wait_inbox_follow_v2`). Mention filtering is an additional match
condition: an exact `@username` token. The v2 follow methods require a
coalescing window of at most 10 seconds and flush at that deadline or
at 32 messages, whichever comes first; termination or local cancellation
also flushes the pending burst. Each method has conforming and
negative fixtures. `make check-chanvoy-daemon-rpc-v0` validates them.

The new method names are separate capabilities. Mention filtering also
extends the existing channel-wait parameter contracts.

### Mail policy v0

`schemas/mail/v0/` defines delegation, one action request, and one
policy decision, plus semantic rules and fixtures.
`make check-mail-v0` validates that family. DDR-0001 records why the
family is separate from the wire and remains Proposed.

## Consumer obligations

Pin the published commit and verify embedded schemas byte-for-byte
against that commit. Record their hashes with the consumer dependency pin.

For local runtime control, enforce the parse policy in
`chanvoy-runtime-control-v1.roots.json`: bounded UTF-8 before parse,
duplicate keys refused, unknown fields and versions refused, and one
JSON object only. Schema validation does not prove process death,
lease release, listener retirement, or readiness. A missing
acknowledgement stays unknown. It is not zero and it is not permission
to force retirement.

For Chanvoy RPC, negotiate by method name. Method-not-found (`-32601`)
is a hard capability failure. Do not treat inbox cursors as post ids,
and do not substitute `wait_follow_v1` events for inbox follow events.
A clean deadline and a provider or ownership failure are different
outcomes. Only the contract's clean-deadman code is a timeout.

For mail policy, carry references, digests, and reason codes. Do not
infer a provider effect from a decision. The numbered MAIL channel
extension stays deferred. The family is v0: pin a commit. There is no
broader compatibility promise.

## Validation

`make check` runs repository guards, schema-family and semantic gates
(including the three gates named above), post-merge epilogue negative
controls, and formatting. `make quality` runs lint. These commands
qualify this contract repository. Consumer conformance and native
lifecycle evidence remain separate work.
